# captain-tsubasa-football-main

运行在浏览器里的六人制像素足球同人项目。JavaScript + Canvas，无后端服务，电脑使用键盘或手柄，手机和平板使用虚拟摇杆。

本仓库只包含独立 Web 版的研发源码、运行素材、构建工具及回归测试。没有 ROM、模拟器程序、发布 ZIP、预编译游戏包、历史实验、私人部署配置或 API Key。游戏运行不需要账号、API Key 或外部 AI 服务。

> **许可范围**：这是非官方同人项目，包含原作角色改编及恢复的图形/声音数据。原创 Web 代码的 MIT 许可不覆盖全部引擎数据和素材，也不代表取得原作授权。使用或再发布前请阅读 [许可范围](LICENSING.md) 和 [第三方说明](THIRD_PARTY_NOTICES.md)。

## 快速开始

需要 Node.js **22.7 或以上**、npm，以及现代浏览器。将下方 `<repository-url>` 替换为本仓库 Code 按钮中的克隆地址。

```sh
git clone <repository-url> captain-tsubasa-football-main
cd captain-tsubasa-football-main
npm ci
npm start
```

打开 <http://127.0.0.1:4180/>。此入口直接加载源码；修改后刷新页面即可。手机设备会进入掌机布局，电脑保持键盘指引，窄窗口不会被强制切换为手机模式。

```sh
# 可使用其他本地端口
PORT=4190 npm start
```

开发服务器只监听本机，勿将它作为公网生产服务器。不要使用 `file://` 直接打开 HTML。

## 玩法与当前能力

- 本地双人对战：1P、2P 独立选择球队，同一台设备上操作；没有网络对战。
- 单人联赛：可自由选择 12 支对手，不按剧情章节锁定顺序。保留积分、赛季交锋上限、梦想杯和密码续关。
- 13 支球队、46 位具名角色；其余阵容位置为改编队员，不宣称全部是原作具名角色。
- 桌面键盘、两路手柄、键位调整、摇杆死区、画面缩放和全屏。
- 手机虚拟摇杆、A/B/跳跃、START/SELECT、横竖屏布局。
- 进球和终场庆祝使用一套共享的六帧身体，按角色换头、按对局换球衣。
- 声音默认开启，浏览器可能要求先点击或触摸一次才能播放。
- 游戏规则、天气和 AI 由本地引擎运行；不依赖云端计算。

| 操作 | 1P | 2P |
| --- | --- | --- |
| 移动 | 方向键 | W / A / S / D |
| 传球 / 确定 | Z | G |
| 射门 / 返回 | X | H |
| 跳跃（A+B） | C | J |
| Start | Enter | T |
| Select | 右 Shift | Y |

桌面可在设置中改键。手柄需先按任意按钮，供浏览器识别。手机 A、B 和摇杆支持多指操作；一套虚拟摇杆控制所选的玩家端口。桌面网页暂停可使用按钮或 Esc；原生 Start 暂停与网页暂停是两层状态。

## 本地存档

联赛在选队、结算后的资格节点、杯赛配对节点及结束节点自动保存。保存积分、胜负/平局形成的交锋记录、场次、难度和联赛阶段；**不保存踢到一半的比分、时间或球员位置**。

- 桌面大厅显示“继续联赛”；手机在有存档时显示继续、新联赛和保留存档的双人对战入口。
- 开始新联赛覆盖存档前需要确认；双人对战不会覆盖联赛进度。
- 存储被拒绝或写入失败会显示提示，仍允许游戏运行。
- `localStorage` 键：`tsubasa-web-league-v1`（联赛）、`tsubasa-web-v1-settings`（桌面设置）。
- 存档属于当前浏览器和网站来源。不同域名或端口不共享，不提供跨设备同步；清除网站数据会删除进度。发布新素材本身不会主动清空存档。

## 构建与静态部署

```sh
npm run build
# npm start 运行时，打开 http://127.0.0.1:4180/dist/ 验证构建结果
```

`dist/` 是独立静态站点，可部署到支持 HTTPS 的静态托管服务，也支持子目录。发布 **dist 的内容**，不要把开发目录或整个仓库当作站点根目录。生产浏览器不需要 Node.js、npm 或远程 CDN。

构建会生成桌面内容指纹脚本、手机 `game.js` 和后台头部预热 Worker；这些文件只存在于 `dist/`，不会提交到 Git。构建工具会检查像素压缩前后导出数据完全一致，不把压缩当作素材删减。

本仓库不绑定任何个人域名、托管平台、云账号或部署密钥，也没有自动线上部署工作流。

## 测试

```sh
npm test
npm run build
npx playwright install chromium
# 另一个终端先运行 npm start
npm run test:browser
```

浏览器测试默认访问 `http://127.0.0.1:4180/dist/`；可用 `BASE_URL` 指定其他本地测试入口。测试会创建独立浏览器上下文，不使用你日常浏览器的存档。

覆盖选队、单人联赛、双路输入、庆祝像素、动画缓存、观众动画、设置、启动失败重试、本地存档及恢复。选队用例从固定菜单起点开始；进球/结算用例用测试夹具设置球路或终场状态，再执行真实引擎处理器，不等于自然操作踢完全部赛程。

截图、测试夹具的临时编译结果和报告写入 `test-results/`，不提交。手机测试使用 Chromium 设备模拟；实体手机、Safari、真实手柄及长时间热机仍需人工验收。

## 开发导航

| 路径 | 用途 |
| --- | --- |
| `src/` | 桌面/手机入口、输入、声音、缩放、本地存档 |
| `engine/src/` | 比赛状态机、物理、AI、菜单、渲染、剧情和声音 |
| `engine/art/` | 当前运行用人物、头像、庆祝及屏幕像素数据 |
| `engine/data/` | 球队、角色和招式定义 |
| `engine/assets/` | 字体和剧情肖像 |
| `mobile/` | 掌机 HTML/CSS 和兼容代码，不含预编译游戏包 |
| `scripts/` | 本地服务、可复现构建和浏览器测试入口 |
| `tests/` | 自动化测试、必要的小型夹具和辅助代码 |
